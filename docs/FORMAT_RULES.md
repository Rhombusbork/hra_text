# HRA 보고서 서식 규칙 (FORMAT_RULES)

이 문서는 프로그램이 **무엇을 검사하고, 어떻게 고치고, 어떤 메모를 다는지**를 정의하는 단일 기준(Single Source of Truth)이다.
코드는 이 문서를 따른다. 규칙을 바꾸려면 **이 문서를 먼저 고치고** 코드를 고친다. (자세한 절차: [CLAUDE.md](../CLAUDE.md) "문서-코드 동기화 규칙")

- 근거 표기: `[T]` 양식 템플릿(HRA20_0조-경영서/기업실무, HRA20_OOO-고전), `[F]` 사용자 피드백 메모(경영서 _피드백.hwpx), `[D]` 사용자 수정 전후 비교(기업실무 재제출→최종), `[U]` 사용자 직접 지시
- 상태: `계획` → `구현` → `검증`(샘플 회귀 테스트 통과). 상태는 **hwpx-xml 브랜치 구현 기준**이다.
- 규칙 ID는 재사용하지 않는다. 폐기/보류된 규칙은 §5로 옮긴다.

## 0. 용어 정리

| 용어 (한글 프로그램) | 단축키 | 의미 | HWPX XML 위치 |
|---|---|---|---|
| **스타일** | F6 | 글자 모양 + 문단 모양을 묶어 이름 붙인 것. "바탕글"은 **스타일 이름**이다 | `hp:p@styleIDRef` → `header.xml hh:style@name` |
| **글자 모양** | Alt+L | 글꼴, 글자 크기, 진하게(볼드), 글자 색 등 | `hp:run@charPrIDRef` → `hh:charPr` |
| └ 글꼴 | | 맑은 고딕 등 | `hh:charPr/hh:fontRef@hangul,latin,...` → `hh:fontface/hh:font@face` |
| └ 글자 크기 | | pt × 100 (10pt = `1000`) | `hh:charPr@height` |
| └ 진하게 | Ctrl+B | | `hh:charPr/hh:bold` 요소 존재 여부 |
| └ 글자 색 | | | `hh:charPr@textColor` |
| **문단 모양** | Alt+T | 정렬, 들여쓰기, 여백, 문단 위/아래 간격, 줄 간격 | `hp:p@paraPrIDRef` → `hh:paraPr` |
| └ 정렬 | | 양쪽/왼쪽/가운데/오른쪽 | `hh:paraPr/hh:align@horizontal` = `JUSTIFY`/`LEFT`/`CENTER`/`RIGHT` |
| └ 들여쓰기(첫 줄) | | 단위 주의(아래 ※) | `hh:margin/hc:intent@value` |
| └ 왼쪽/오른쪽 여백 | | 단위 주의(아래 ※) | `hc:left`, `hc:right` |
| └ 문단 위/아래 간격 | | 단위 주의(아래 ※) | `hc:prev`, `hc:next` |
| └ 줄 간격 | | % | `hh:lineSpacing@type="PERCENT" @value` |
| **셀 음영(배경)** | 표 > 셀 테두리/배경 (L) | 표 칸의 배경색 | `hp:tc@borderFillIDRef` → `hh:borderFill/hc:fillBrush` |
| **머리행** | | 표의 첫 줄(제목 줄). 예: "배경 / 제도의 목적" | `hp:tbl/hp:tr[1]` |
| **글자처럼 취급** | 개체 속성 | 표/그림이 글자 한 개처럼 줄 안에 놓이게 하는 옵션 | `hp:tbl/hp:pos@treatAsChar`, `hp:pic/hp:pos@treatAsChar` = `1` |
| **쪽 번호** | 쪽 > 쪽 번호 매기기 | | `hp:ctrl/hp:pageNum`, 머리말/꼬리말 안 `hp:autoNum[@numType=PAGE]` |
| **메모** | 입력 > 메모 | 본문 범위에 다는 코멘트 | `hp:ctrl/hp:fieldBegin@type="MEMO"` … `hp:fieldEnd` |

> ※ **문단 여백·간격 단위 (샘플·hwp2hwpx 소스로 확인)**: `hh:paraPr`의 여백은 두 형태로 저장된다.
> - `hp:switch/hp:case[@required-namespace=".../HwpUnitChar"]/hh:margin` — **1pt = 100** (10pt = `1000`). 최신 한글이 읽는 값. `unit="CHAR"`면 글자 단위.
> - `hp:switch/hp:default/hh:margin` 또는 switch 없이 바로 있는 `hh:margin` — **1pt = 200** (10pt = `2000`). 피드백본(한글 저장)이 이 형태.
> - 줄 간격도 같은 구조(`hp:case`와 `hp:default`의 `hh:lineSpacing`). 수정할 때는 **두 형태를 모두** 같은 pt 값으로 맞춘다.
>
> ※ **텍스트 추출**: `hp:t` 안에 `hp:tab`, `hp:lineBreak` 같은 요소가 끼어 있을 수 있다. 글자를 읽을 때 각 요소의 tail 텍스트까지 포함한다.

> 예: "출처는 **바탕글 스타일**, **글꼴** 맑은 고딕, **글자 크기** 8pt, **정렬** 오른쪽"

## 1. 문단 역할(Role) 분류

모든 규칙은 "이 문단이 무엇인가"에 따라 기대값이 다르다. 먼저 역할을 분류한다. 구현: `hra_text/classify.py` (역할 ID 상수는 이 표와 같아야 한다).
`hra-fix dump <파일>` 로 문단별 분류 결과를 확인할 수 있다.

| 역할 ID | 이름 | 판별 기준 (위에서부터 먼저 맞는 것) | 근거 |
|---|---|---|---|
| `SKIP` | 처리 안 함 | 메모 내용, 머리말/꼬리말, 각주/미주, 글상자 안 문단 | — |
| `GUIDE` | 양식 안내문 | 보이는 글자가 **모두** 빨강(`#FF0000`)인 문단 (예: "본문내용(맑은 고딕, 10…)", "* 쪽 번호를 없앤 뒤…"). 일부만 빨강이면(예: "■ 고전명작 **발표자용**") 문단 역할은 따로 정하고 빨간 런만 R15가 지운다 | [T][U] |
| `INTRO_TITLE` | 책 소개 표 제목 칸 | **책 소개 표** = 2×2 표, 첫 줄이 두 칸 병합, (그림이 있거나 "…소개" 1단위 타이틀 아래). 그 첫 줄 | [T] |
| `INTRO_IMAGE` | 책 소개 표 그림 칸 | 책 소개 표에서 그림(또는 "그림" 자리표시)이 있는 칸의 모든 문단 | [T] |
| `INTRO_BODY` | 책 소개 표 내용 칸 | 책 소개 표의 나머지 칸 문단 (출처 줄은 SOURCE) | [T] |
| `TOC_TITLE` | 목차 제목 | "목차" 표 안의 `목차` 문단 | [T] |
| `TOC_ITEM` | 목차 항목 | "목차" 표 안의 나머지 문단 (`Ⅰ.`로 시작해도 H1 아님) | [T] |
| `COVER_TABLE` | 표지 정보 표 | 셀 글자(공백 제거)에 소속/조원/발표자/담당교수/발표일 중 2개 이상이 있는 표 | [T] |
| `H1` | 1단위 타이틀 | ① **1×1 표 안에 흰 글씨만 있는 문단** (템플릿의 검정 그라데이션 칸), 또는 ② `Ⅰ.`~`Ⅹ.`로 시작 | [T] |
| `SOURCE` | 출처/참고자료 | `^\s*(사진\s*)?(출처|참고 자료|자료)\s*:` (표 안이어도 SOURCE) | [T][F][U] |
| `TABLE_CELL` | 일반 표 안 문단 | 위에 해당하지 않는 표 셀 문단 | [D] |
| `CATEGORY` | 분류 표시 | `■`로 시작 (■ 경영서 / ■ 기업실무 / ■ 고전명작). 두 번째 ■ 부터는 고전 "함께읽기용" 부분의 시작 | [T] |
| `EMPTY` | 빈 줄 | 글자도 개체도 없음 | [F] |
| `OBJECT` | 개체 문단 | 글자 없이 표/그림만 있음 | [T][F] |
| `COVER_TITLE` | 표지 제목 | 첫 1단위 타이틀 앞(표지 영역)의 글자 문단 중 20pt 이상 | [T] |
| `READING_TITLE` | 함께읽기용 제목 | 두 번째 ■ 다음 첫 글자 문단. **1단위 타이틀이 하나도 없는 문서(에세이)는 첫 ■ 다음 첫 글자 문단** — 에세이는 고전 '함께읽기용'과 같은 형식 | [T] 샘플 |
| `READING_BYLINE` | 함께읽기용 작성자 줄 | 함께읽기용 부분의 `HRA 20기 …` 줄 | [T] |
| `AUTHOR_TAG` | 작성자 표기 | `<…작성자: …>` | 샘플 [U] |
| `H2` | 2단위 타이틀 | `^\s*\d{1,2}\.(?!\d)\s*\S` (예: `1. `, 소수점 `1.5`는 제외) | [T] |
| `H3` | 3단위 타이틀 | `^\s*\d{1,2}\)\s*\S` (예: `1) `) | [T] |
| `H4` | 4단위 타이틀 | `^\s*[①-⑳]` | [T] |
| `REFLECTION_NAME` | 느낀 점 이름 줄 | 1단위 타이틀에 "느낀 점/소감/후기"가 들어간 영역에서 한글 2~4자만 있는 문단 (예: `이예나`) | 샘플 [U] |
| `REFLECTION` | 느낀 점 본문 | 그 영역의 나머지 글자 문단 | 샘플 |
| `BODY` | 본문 | 위에 해당하지 않는 글자 문단 | [T] |

## 2. 규칙 목록

각 규칙의 형식: **ID / 대상 역할 / 기대값 / 감지 / 수정 / 메모 템플릿 / 근거 / 상태**

모든 규칙은 "필요한 서식을 넣는 것"과 함께 "**들어가면 안 되는 서식을 빼는 것**"을 포함한다. 기대값과 다른 값은 무엇이든 기대값으로 덮어쓴다.

### R01. 스타일은 전부 "바탕글"
- 대상: 전체 (메모 내부 제외)
- 기대값: `styleIDRef` → `바탕글`
- 감지: 스타일 이름이 `바탕글`이 아닌 문단 (예: `본문`, `MS바탕글`, `제목 1`, `제목 2`)
- 수정: 바탕글 스타일 ID로 교체. 글자/문단 모양은 이후 규칙이 명시적으로 지정
- 메모: `문단 스타일이 '{old}'(으)로 설정되어 있어 '바탕글'로 수정했습니다. 다른 문서에서 복사해 오실 때 스타일이 함께 따라오는 경우가 많으니, 붙여넣기 후 F6에서 바탕글로 맞춰 주시면 감사드리겠습니다.`
- 근거: [U][D][F] · 상태: 구현

### R02. 글꼴은 전부 "맑은 고딕"
- 대상: 전체 텍스트 (한글/영문/숫자 등 모든 언어 슬롯)
- 기대값: `fontRef`의 모든 언어 → `맑은 고딕`
- 감지: 다른 글꼴 (예: 제목 앞 공백이 Calibri)
- 수정: 맑은 고딕으로 교체 (fontface에 없으면 추가)
- 메모: `일부 글자가 '{old}' 글꼴로 되어 있어 맑은 고딕으로 수정했습니다.`
- 근거: [T] · 상태: 구현

### R03. 역할별 글자 크기·진하게

| 역할 | 크기 | 진하게 |
|---|---|---|
| CATEGORY | 12pt | O |
| COVER_TITLE | 32pt | O |
| TOC_TITLE | 16pt | X |
| TOC_ITEM | 12pt | O |
| INTRO_TITLE | 12pt | O |
| INTRO_IMAGE, INTRO_BODY | 10pt | X |
| READING_TITLE | 12pt | O |
| READING_BYLINE | 11pt | X |
| COVER_TABLE | 11pt | O |
| H1 | 12pt | O |
| H2 | 12pt | O |
| H3 | 11pt | O |
| H4 | 10pt | X |
| REFLECTION_NAME | 10pt | **O** (본문 볼드 금지의 예외) |
| BODY, REFLECTION 본문 | **10pt** | **X (부분 강조도 해제)** |
| TABLE_CELL | 10pt | **X (머리행 포함)** |
| SOURCE | 8pt | X |
| AUTHOR_TAG | 8pt | X |

- 처리 범위: 글자가 있는 런(공백 포함)만 바꾼다. 빈 줄(EMPTY)·개체 문단(OBJECT)·안내문(GUIDE)은 R03 대상이 아니다. **SOURCE는 R08이 처리**한다.
- 참고: H4는 템플릿 설명이 "10"이지만 설명 글자 자체는 11pt로 쓰여 있다. 설명(10pt)을 따른다.
- R03-a 크기: 역할의 기대값과 다르면 수정.
  메모: `{old}포인트로 되어 있어 {new}포인트로 수정했습니다. 앞으로 주의해주시면 감사드리겠습니다.`
- R03-b 진하게: 위 표에서 O인 역할은 진하게를 넣고, X인 역할은 **모두 뺀다** (본문 안 일부 단어 볼드도 해제).
  메모(넣음): `타이틀이 진하게 설정되어 있지 않아 진하게로 수정했습니다.` / 메모(뺌): `본문에는 진하게를 사용하지 않습니다. 진하게를 해제했습니다.`
- 근거: [T][F][D][U] · 상태: 구현

### R04. 정렬

| 역할 | 정렬 |
|---|---|
| COVER_TITLE, TOC_TITLE, TOC_ITEM, COVER_TABLE, INTRO_TITLE, INTRO_IMAGE, READING_TITLE | 가운데 |
| SOURCE, AUTHOR_TAG, READING_BYLINE | 오른쪽 |
| 그 외 전부 (H1~H4, BODY, TABLE_CELL, INTRO_BODY 등) | **양쪽** |
| OBJECT (표·그림을 담은 문단) | **받은 대로 (손대지 않음)** |
| EMPTY (빈 줄) | 받은 대로 (정렬이 화면에 보이지 않음) |

- **개체 문단(OBJECT = 표 바깥 문단 = 표 자체의 위치)은 받은 대로 둔다** [U] 2026-10-29. 표는 글자처럼 취급(R07)만 맞춘다. 표 **안** 글자는 TABLE_CELL 규칙대로 양쪽. (경과: 표 종류별 위치 → 일반 표 가운데 → 왼쪽 → 최종적으로 '손대지 않음'.)
- SOURCE는 R08이 처리한다.
- INTRO_BODY는 템플릿 자리표시("내용")가 가운데 정렬이지만 실제 내용은 양쪽 정렬로 한다 [U] 2026-10-29.

- 메모: `{old} 정렬로 되어 있어 {new} 정렬로 수정했습니다.` — 양쪽으로 바꿀 때는 뒤에 `중간중간 왼쪽 정렬과 양쪽 정렬이 섞이지 않도록 양쪽 정렬로 통일해 주시면 감사드리겠습니다.`를 붙인다. 바뀐 정렬(양쪽/가운데/오른쪽)마다 첫 메모는 전체 문장.
- 근거: [U][F][D] · 상태: 구현

### R05. 들여쓰기·여백

| 역할 | 첫 줄 들여쓰기 | 왼쪽/오른쪽 여백 |
|---|---|---|
| CATEGORY, COVER_*, TOC_*, H1, READING_TITLE, READING_BYLINE | 0 | 0 |
| H2, H3, H4, BODY, REFLECTION_NAME, REFLECTION | **10pt** (`2000`) | 0 |
| SOURCE, AUTHOR_TAG | 0 | 0 |
| OBJECT (표/그림 문단) | **0 (들여쓰기 없음)** | 0 |
| TABLE_CELL, INTRO_* | 0 | 0 |

- 빈 줄(EMPTY)은 보이지 않으므로 건드리지 않는다. SOURCE는 R08이 처리한다.
- 참고: 사용자 피드백본은 2·3단위 타이틀 중에도 0pt(4장·6장·9장 등)와 10pt가 섞여 있다. 템플릿 기준(위 표)을 따른다.
- 메모: `들여쓰기가 {old}pt로 되어 있어 {new}pt로 수정했습니다. Alt T(문단 모양)에서 확인하실 수 있습니다.` / `왼쪽 여백이 {old}pt로 설정되어 있어 0으로 수정했습니다.` / `오른쪽 여백이 {old}pt로 설정되어 있어 0으로 수정했습니다.`
- 근거: [T][D][F] · 상태: 구현

### R06. 문단 위/아래 간격 = 0, 줄 간격 = 160%
- 대상: 전체 (표 안 포함)
- 기대값: `prev=0`, `next=0`, `lineSpacing PERCENT 160`
- 감지: 그 외 값 (예: 아래 간격 4pt, 위/아래 1pt, 줄 간격 110%)
- 메모: `이 부분의 문단 {pos} 간격이 어째서인지 {old}pt로 설정되어 있었습니다. 0으로 수정했으니 {pos} 간격을 설정하지 않아 주시면 감사드리겠습니다.` ({pos} = 위/아래) / `줄 간격이 {old}%로 되어 있어 160%로 수정했습니다.`
- 근거: [F][D] · 상태: 구현

### R07. 표·그림은 "글자처럼 취급" + 들여쓰기 없음
- 대상: 모든 `hp:tbl`, `hp:pic` (중첩 포함)
- 기대값: `hp:pos@treatAsChar="1"`, 개체가 든 문단 들여쓰기 0
- 주의(배치 순서): 글자처럼 취급이 꺼진 개체는 문단 안 위치(앵커)와 화면 위치가 다를 수 있다. 예: 경영서 샘플은 책 소개 표(떠 있는 표)가 `Ⅰ. 책 소개` 타이틀 칸과 **같은 문단**에, 타이틀 칸보다 **앞**에 앵커되어 있다. 옵션만 켜면 표가 타이틀 앞으로 끌려온다.
  - 수정: 떠 있던 개체가 다른 개체/글자와 같은 문단에 있고 **문단 기준**(`hp:pos@vertRelTo="PARA"`)으로 떠 있으면, 세로 위치(`vertOffset`) 순서대로 개체마다 **새 문단으로 옮겨 원래 문단 뒤에** 둔 뒤 글자처럼 취급을 켠다. (원래 문단의 글자·글자처럼 취급된 개체가 맨 위에 있으므로 그 뒤가 화면 순서와 같다.) 문단에 떠 있는 개체만 여러 개면 첫 개체는 원래 문단에 남긴다.
  - 쪽/용지 기준으로 떠 있던 개체가 섞여 있으면 순서를 확신할 수 없으므로 옵션만 켜고 메모로 위치 확인을 요청한다 (변경 기록 note: "배치 확인 필요").
  - 새 문단은 원래 문단의 스타일·문단 모양을 복사한다 (이미 R04·R05로 맞춘 개체 문단 모양).
- 메모: `{kind} 글자처럼 취급 꼭 해주시면 감사드리겠습니다. 글자처럼 취급으로 수정했습니다.` ({kind} = 표/사진) — 배치 확인이 필요하면 `원래 위치가 쪽 기준이라, 배치가 맞는지 한 번 확인 부탁드립니다.`를 붙인다. 메모는 옮겨진 개체(표면 그 표 안 첫 글자 문단)에 단다.
- 근거: [T][F][U] · 상태: 구현

### R08. 출처·각주
- 대상: SOURCE
- 기대값: 바탕글 스타일 / 맑은 고딕 / 8pt / 오른쪽 정렬 / 들여쓰기 0 / 진하게 X
- 처리: 스타일·글꼴·간격은 R01·R02·R06이 맞추고, R08은 크기·진하게·정렬·들여쓰기/여백을 맞춘다 (R03~R05는 SOURCE를 건너뜀).
- 참고: 사용자 수정 예시(기업실무 최종본)의 `출처: [1] …` 줄은 10pt·양쪽·들여쓰기 10으로 남아 있으나 수정 누락이다 [U] 2026-10-29. 회귀 비교 시 이 줄은 예시가 아니라 규칙을 따른다.
- 메모: `출처의 경우 맑은 고딕 8pt, 오른쪽 정렬을 지켜주시면 감사드리겠습니다. ({details})` ({details} 예: `글자 크기 10pt→8pt, 정렬 양쪽→오른쪽`)
- 근거: [T][U] · 상태: 구현

### R09. 빈 줄 정리
- 대상: 본문 영역(첫 1단위 타이틀부터)의 바깥 문단 사이 빈 줄. 표지 영역은 건드리지 않는다.
- 앞 문단 X, 뒤 문단 Y 사이 빈 줄 수 — **줄이기만 하고 새로 넣지는 않는다** [U][D] (사용자 수정본도 빈 줄을 넣지 않음):
  - R09-b·c: X가 타이틀(1단위 칸·H2·H3·H4)이면 **0** (2단위·3단위 타이틀, 타이틀과 그 아래는 붙여 쓴다)
  - R09-a: 그 외에는 **최대 1** (여러 줄이면 한 줄로)
  - Y가 ■ 분류 표시(고전 '함께읽기용' 등 새 부분의 시작)면 건드리지 않는다 (부분을 나누는 빈 줄)
  - 쪽 나누기·컨트롤·구역 정의가 든 빈 문단은 지우지 않는다
- 메모(빈 줄을 지운 자리 다음 문단에 단다):
  - 여러 줄 → 한 줄: `이 부분이 너무 많이 띄어져 있었습니다. 한 줄만 띄어주시면 감사드리겠습니다.`
  - 2단위 다음 3단위: `2단위 타이틀과 3단위 타이틀은 붙여 써 주시면 감사드리겠습니다. 아마 문단 위 문단 아래에 간격 설정이 되어 있고, 바탕글로 설정되지 않아 발생하신 문제인 듯 합니다. Alt T로 확인하고 진행해 주시거나, Alt C 의 문단 모양 복사를 통해 문단 모양이 지켜진 양식에서 복사해 수정해 주시면 감사드리겠습니다.`
  - 그 외 타이틀 아래: `타이틀 바로 아래에는 빈 줄 없이 붙여 써 주시면 감사드리겠습니다. 빈 줄을 지웠습니다.`
- 근거: [F][D][U] · 상태: 구현

### R10. 텍스트 앞 불필요한 공백 제거
- 대상: H1~H4, BODY, AUTHOR_TAG, REFLECTION_NAME, REFLECTION
- 감지: 문단 맨 앞 공백(스페이스, 전각 공백, 탭) — 들여쓰기·오른쪽 밀기를 공백으로 흉내 낸 경우 (예: `  5. 4장…`, 작성자 표기 앞 공백 68칸)
- 수정: 첫 글자가 나올 때까지 앞 공백 제거 (들여쓰기는 R05, 오른쪽 정렬은 R04가 맞춘다)
- 메모: `문단 앞에 띄어쓰기로 들여쓰기가 되어 있어 지웠습니다. 들여쓰기는 Alt T(문단 모양)로 설정해 주시면 감사드리겠습니다.`
- 근거: 샘플 관찰 · 상태: 구현

### R11. 띄어쓰기·맞춤법 (규칙·사전 기반)
- R11-a 규칙 기반 (확실한 패턴만 자동 수정)
  - `(\S+학과)(\d학년)` → `\1 \2` (예: 경영학과4학년 → 경영학과 4학년)
  - 그 외 패턴은 발견 시 이 목록에 추가
- R11-b 사전 기반 교정 목록 `hra_text/rules/spacing_dict.tsv` (예: `직종별유연근무제제안 → 직종별 유연근무제 제안`). 새 사례가 나오면 사전에 추가
- 메모: `'{old}'를 '{new}'(으)로 띄어 썼습니다.`
- 근거: [D][U] · 상태: 계획

### R13. 잘못 가해진 추가 서식 제거 (기본값 복원)
위 규칙이 명시하지 않은 서식도 **양식 기본값과 다르면 기본값으로 되돌린다.**
- 글자 모양: 기울임, 밑줄, 취소선, 외곽선, 그림자, 양각, 음각, 위/아래 첨자, 글자 색(검정 외), 글자 음영, 장평 ≠ 100%, 자간 ≠ 0
- 문단 모양: 문단 테두리/배경, "다음 문단과 함께"
- 표: **일반 표의 셀 배경(셀 음영) 제거** (테두리 선은 그대로). 책 소개 표는 제목 칸(첫 줄)만 유지하고 나머지 칸 배경은 제거.
- 유지(예외): 템플릿 디자인 — 1단위 타이틀 칸의 검정 그라데이션 배경 + 흰 글씨, 표지 정보 표 항목명의 검은 셀 배경과 회색(`#E5E5E5`) 글씨, 목차 표, 책 소개 표 제목 칸의 회색 배경. **하이퍼링크 글자의 색·밑줄**.
- 흰색(`#FFFFFF`) 배경은 배경 없음과 같게 본다.
- 다루지 않음(현재): 줄 나눔 기준(한글/영어 단위), 공백 최소값 — 문서마다 달라 기본값이 확실하지 않음.
- 메모: `{item}이(가) 설정되어 있어 기본값으로 되돌렸습니다.` (예: `기울임이(가) 설정되어 있어…`, `셀 음영이(가) 설정되어 있어…`)
- 근거: [U][F][T] (템플릿 디자인 예외 유지는 [U] 2026-10-29 확인) · 상태: 구현

### R14. 목차 대조 (메모만, 자동 수정 X)
- 목차 항목(TOC_ITEM)과 본문 1단위 타이틀(H1)을 순서대로 비교한다 (띄어쓰기 무시).
  - 글자가 다르면: `목차의 '{toc}'와 본문 타이틀 '{h1}'이 서로 다릅니다. 확인 부탁드립니다.`
  - 개수가 다르면: `목차 항목은 {toc}개인데 본문 1단위 타이틀은 {h1}개입니다. 확인 부탁드립니다.`
- 알림만 하는 변경이라(변경 기록 `check`), 목차 표에 이미 이 지적 메모가 있으면(결과를 다시 넣은 경우) 다시 달지 않는다.
- 표지 정보 표의 글자 서식(가운데, 11pt 진하게, 간격 0)은 R03·R04·R06이 맞춘다.
- 근거: [D][U] · 상태: 구현

### R15. 양식 안내문(붉은 글씨) 삭제
- 대상: 글자 색 `#FF0000` 런 (본문·표 안)
- 예: `발표자용`, `함께읽기용`, `본문내용(맑은 고딕, 10, 들여쓰기 10)`, `* 표, 그림(들여쓰기 없음, 글자취급 체크)`, `* 쪽 번호를 없앤 뒤 보내주시기 바랍니다.`
- 수정: 빨간 런의 글자 삭제. 남은 글자가 없고 개체·컨트롤·쪽 나누기도 없으면 문단째 삭제 (이후 R09가 빈 줄 정리). 일부만 빨간 문단(예: `■ 고전명작 발표자용`)은 빨간 글자만 지운다.
- 메모(지운 문단이면 다음 글자 문단, 아니면 그 문단): `양식 안내 문구('{text}')가 남아 있어 삭제했습니다.`
- 근거: [T][U] · 상태: 구현

### R16. 쪽 번호 제거
- 대상: 구역 전체 (`hp:ctrl/hp:pageNum` 쪽 번호 매기기, 머리말/꼬리말 안 `hp:autoNum[@numType="PAGE"]`)
- 근거 문구: 템플릿 "쪽 번호를 없앤 뒤 보내주시기 바랍니다."
- 수정: 쪽 번호 컨트롤 삭제
- 메모(문서 첫 글자 문단): `쪽 번호가 들어가 있어 삭제했습니다. 쪽 번호를 없앤 뒤 보내주시면 감사드리겠습니다.`
- 근거: [T] · 상태: 구현

## 3. 메모(코멘트) 작성 원칙

[F] 피드백 메모의 문체를 따른다. 구현: `hra_text/memo.py`(묶기·문구), `hra_text/hwpx/memo.py`(XML 삽입), 문구: `hra_text/rules/memo_templates.py`.

1. **현상** — "~로 되어 있었습니다", "~가 섞여 있었습니다"
2. **조치/요청** — "~로 수정했습니다" / "~해 주시면 감사드리겠습니다"
3. **방법 안내(선택)** — "Alt T로 들여쓰기 확인하고…", "F6에서 바탕글로…"
4. **도움 문구(문서당 1회, 첫 메모 끝)** — `혹시 도움이 필요하신 부분이 있으시다면 말씀해주세요.`

**고친 것마다 메모를 단다** [U]. 단, 메모가 수백 개로 늘지 않도록 다음처럼 묶는다 (2026-10-29):

| 고친 곳 | 메모를 다는 곳 | 메모 수 |
|---|---|---|
| 본문 문단 | 그 문단의 글자 전체 | 문단 1개당 1개 (여러 규칙은 한 메모에 줄을 나눠 적음) |
| 표 안 문단, 표를 담은 문단 | 그 표 안의 첫 글자 문단 | **표 1개당 1개**. 첫 줄 `이 표 안의 문단 {n}개를 다음과 같이 수정했습니다.` |
| 빈 줄 | 같은 영역의 다음 글자 문단 메모에 합침 | 줄 추가: `위쪽 빈 줄 {n}개의 서식도 같은 기준으로 맞췄습니다.` |
| 그림만 있는 문단 | 같은 영역의 다음 글자 문단 메모에 합침 | — |

- **같은 수정이 이어지면 메모는 처음 한 번만** [U] 2026-10-29: 문서 순서로 바로 앞 메모와 고친 내용(규칙·항목·이전값·새값)이 같고 종류(문단/표)도 같으면 새 메모를 달지 않고, 앞 메모에 `아래 {what} {n}개도 같은 문제가 있어 같이 수정했습니다.`를 붙인다 ({what} = 문단/표). 다른 수정이 나오면 다시 메모를 단다.
- R13·R14·R15·R16 메모는 내용이 그때그때 달라 **매번 전체 문장**으로 쓴다.
- 같은 (규칙, 항목)의 **첫 메모는 §2 템플릿 전체 문장**, 두 번째부터는 짧은 형태 `{item}: {old} → {new} 수정했습니다.` (예: `스타일: MS바탕글 → 바탕글 수정했습니다.`)
- 한 메모 안에서 같은 내용(같은 규칙·항목·이전값·새값)은 한 줄로 합친다.
- 메모 안 순서: 규칙 순서(CLAUDE.md 패스 순서) → 항목 순서(글자처럼 취급, 스타일, 글꼴, 크기, 진하게, 정렬, 들여쓰기, 왼쪽/오른쪽 여백, 위/아래 간격, 줄 간격).
- 메모 문단은 문서의 `메모` 스타일(없으면 바탕글)을 쓴다. 작성자(Author)는 `--author`(기본 `neoju`).
- 원래 있던 메모는 그대로 두고, 번호는 기존 메모 다음부터 매긴다.
- 삭제(R09 빈 줄, R15 안내문) 메모는 삭제된 자리 **다음 문단**에 단다 (7단계).
- 메모 문구 템플릿의 원본은 이 문서이며, `memo_templates.py`는 이 문서와 같아야 한다 (`tests/test_rules_sync.py`).
